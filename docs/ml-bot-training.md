# ML bot policy v5 training

The Website owns the schema-v5 observation/action contract, deterministic
Boneyard training environment, PyTorch trainer, evaluation artifacts, and
compact runtime checkpoint. Attaching a trained policy to a live game client
is intentionally outside this training package.

## Contract

- Observation width: 1,784 ordered float32 values.
- Action order: movement (9), target (9), ability (22), aim (9).
- Autoregressive legality: target selects an ability-mask row; ability selects
  an aim-mask row. Masks encode legality only.
- Choice descriptors: 56 values per offered skill.
- Observation, model, main trajectory, and choice trajectory versions: 5.
- Runtime checkpoint: compact `SDMLV5` binary. Versions 1-4 have no shim.
- Network: two tanh trunk layers, 1,784 → 512 → 256; four policy heads and
  value; 312 → 128 option scorer and separate choice value.

The ordered contract is generated by
`frontend/tools/generate-ml-bot-policy-spec.mjs` into
`frontend/src/game/core-server/ml-bot-policy/policy-spec-v5.json`. Python loads
that artifact directly before constructing a model or taking a gradient step.

## Mac training environment

Create an isolated environment outside the Git worktree:

```sh
python3 -m venv /path/to/ml-bot-venv
/path/to/ml-bot-venv/bin/python -m pip install \
  -r tools/ml_bot/requirements.txt
```

The pinned campaign stack is Python 3.12, NumPy 2.5.2, and PyTorch 2.13.0.
Run the boundary test before training:

```sh
/path/to/ml-bot-venv/bin/python tools/train_bot_policy.py self-test
```

That test crosses the TypeScript spec, compact checkpoint codec, PyTorch
inference, BC, main PPO, choice SMDP PPO, Node worker bridge, expert action,
and selective-reset boundaries.

## Bootstrap and training

The bootstrap collects real authoritative web states and labels them with the
TypeScript semantic expert. It caps uninteresting opening rows and fails if
the dataset does not cover multiple movement, target, and ability actions.

```sh
python tools/train_bot_policy.py bootstrap \
  --output runtime/ml-training/web-v5 \
  --samples 6000 \
  --bootstrap-epochs 20 \
  --worlds 8 --workers 8 --action-repeat 10
```

Start PPO from the resulting checkpoint. Every run requires an experiment
change, expected metric, and evaluation condition; they are appended to
`experiments.md` before collection.

```sh
python tools/train_bot_policy.py train \
  --checkpoint runtime/ml-training/web-v5/bootstrap-v5.sdml \
  --output runtime/ml-training/web-v5 \
  --iterations 10 --rollout-steps 512 \
  --worlds 8 --workers 8 --action-repeat 10 \
  --gamma 0.995 --learning-rate 0.0001 --target-kl 0.02 \
  --experiment "Schema-v5 PPO with target-KL stop" \
  --expected-metric "holdout wave depth increases" \
  --eval-condition "frozen train-dist and holdout seeds"
```

Main rewards remain raw and frozen. A running standard deviation of discounted
returns scales rewards before tick-aware GAE. Each decision uses
`gamma ** executed_ticks`; an action repeat stops on the first terminal tick.
The approved gamma values are 0.99, 0.995, 0.997, and 0.999.

Skill choices in the current web runtime are scripted and carry
`trainable=false`. They are recorded but excluded from SMDP batches. The
separate choice scorer, normalized entropy, coverage temperature, variable
duration advantages, optimizer, and checkpoint state remain implemented for
learned-choice experiments.

## Resume and validate

Runtime and trainer checkpoints are atomically replaced. Resume is allowed
only when the supplied `.sdml` hash, progress counters, and immutable training
configuration match the saved trainer state.

```sh
python tools/train_bot_policy.py train \
  --checkpoint runtime/ml-training/web-v5/latest.sdml \
  --output runtime/ml-training/web-v5 --resume \
  [the same training arguments]

python tools/train_bot_policy.py validate \
  --checkpoint runtime/ml-training/web-v5/latest.sdml
```

Validation loads the same checkpoint in Python and TypeScript and compares a
fixed-input action/value/log-probability result.

## Evaluation and diagnostics

`tools/ml_bot/eval-seeds.json` freezes 30 train-distribution and 30 holdout
seeds. Comparative claims require both sets.

```sh
python tools/train_bot_policy.py evaluate \
  --checkpoint runtime/ml-training/web-v5/latest.sdml \
  --seed-set eval_train_dist \
  --report runtime/ml-training/web-v5/eval-train.json

python tools/train_bot_policy.py evaluate \
  --checkpoint runtime/ml-training/web-v5/latest.sdml \
  --seed-set eval_holdout \
  --report runtime/ml-training/web-v5/eval-holdout.json

python tools/train_bot_policy.py probes \
  --checkpoint runtime/ml-training/web-v5/latest.sdml \
  --dataset runtime/ml-training/web-v5/expert-v5.npz \
  --output runtime/ml-training/web-v5/probes.json

python tools/train_bot_policy.py diagnostics \
  --training-directory runtime/ml-training/web-v5 \
  --output runtime/ml-training/web-v5/dashboard.html
```

Each update records learning metrics plus exact gameplay outcomes: enemy kills
and kinds, waves reached/completed, deaths, potion use, skill picks, gold,
item kinds/counts, health/mana orbs, powerups, XP, reward decomposition, and
action histograms. Per-update observation audits, value calibration, and a
spatial replay JSONL are written alongside checkpoints. Render a replay with:

```sh
python tools/train_bot_policy.py replay \
  --source runtime/ml-training/web-v5/replays/update-000001-world-0.jsonl \
  --output runtime/ml-training/web-v5/replay-000001.html
```

Both HTML artifacts are self-contained and read-only.
